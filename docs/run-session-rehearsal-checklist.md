# 跑团彩排清单（Run Session Rehearsal Checklist）

真实跑团前至少完整走一遍。建议提前 1–2 周做首次彩排，跑团前一天再快速过一遍。

## A. 启动（本地彩排）

- [ ] `npm run server:dev` — Room Server 启动，日志显示监听地址与 CORS 白名单
- [ ] `npm run dev` — 前端启动
- [ ] 加入入口处「房间服务」显示 **已连接**（绿色）
- [ ] （云端彩排改用：Netlify 站点 + 云端 Room Server，见 docs/room-server-deployment.md）

## B. 建房与加入

- [ ] 主持人：战役详情 → 开启局域网房间，拿到房间码
- [ ] 玩家（另一浏览器/设备）：加入入口输入房间码 + 昵称
- [ ] 主持人在大厅看到待审批成员 → 批准
- [ ] 玩家提交角色绑定 → 主持人批准角色
- [ ] 玩家点「准备」，状态变为已准备

## C. 进入 Runtime

- [ ] 主持人进入 Runtime，底部行动坞显示：投骰 / 公开信息 / 状态记录 / 场景 / 日志 / 更多
- [ ] 玩家进入 Runtime，行动坞显示：投骰 / 我的角色 / 公开信息 / 日志（**无**状态记录/场景/更多）
- [ ] 旁观者（如有）：公开信息 / 日志 / 视角，**无投骰**

## D. 核心动作

- [ ] 主持人投骰（如 1d20+5）→ 双方日志出现结构化骰子结果
- [ ] 玩家投骰 → 双方日志可见（服务器掷骰）
- [ ] 主持人「公开信息」发布一条（含标题）→ 玩家打开「公开信息」能看到；日志出现该条
- [ ] 主持人「状态记录」记一条（如 阿尔文 HP -5）→ 玩家日志可见，标注"手动记录，不影响角色卡"
- [ ] 日志抽屉能回看以上全部；「刷新日志」正常

## E. 异常与恢复

- [ ] 关闭 Room Server → 前端提示"房间服务未连接/连接异常"，页面不崩
- [ ] 重启 Room Server → **注意：内存房间已丢失，需要重新建房**（当前已知限制）
- [ ] 玩家刷新页面后能否回到房间？（v0 需重新加入 — 提前告知玩家不要随手刷新）

## F. 跑团当天注意事项

- 跑团期间 **不要重启 Room Server**（房间在内存里，重启=全灭）
- 提前把房间码/站点地址发到群里；备一个语音频道
- 主持人开一个备用浏览器标签当"旁观者"，方便核对玩家视角
- 骰子语法：`d20`、`2d6+3`、`1d100`；不支持优势/惩罚骰语法，需要时各掷一次
- 状态变化只是日志记录，角色卡数值需玩家自己改
- 出问题先看：房间服务状态徽章 → 刷新日志 → 最后才考虑重建房间
